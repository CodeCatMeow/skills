# uv

uv is an extremely fast Python package and project manager. It replaces pip,
pip-tools, pipx, pyenv, virtualenv, poetry, etc.

Prefer the modern uv project workflow with `pyproject.toml` and `uv.lock`.
Only use the `uv pip` compatibility interface when explicitly requested by the
user.

## When to use uv

**Always use uv for Python work**, especially if you see:

- A `pyproject.toml` file
- A `uv.lock` file
- uv headers in `requirements*` files, e.g., "This file was autogenerated by uv"

Don't mix uv into projects managed by other tools unless migration is
explicitly requested:

- Poetry projects (identifiable by `poetry.lock`)
- PDM projects (identifiable by `pdm.lock`)

## Choosing the right workflow

### Scripts

**Use when:** Running single Python files and standalone scripts.

**Key commands:**

```bash
uv run script.py                      # Run a script
uv run --with requests script.py      # Run with a temporary dependency
uv add --script script.py requests    # Add dependencies inline to the script
```

### Projects

**Use when:** Creating or working with a Python project.

**Key commands:**

```bash
uv init                   # Create a new project
uv init --bare            # Add minimal metadata to existing source
uv add requests           # Add a runtime dependency
uv add --dev pytest       # Add a development dependency
uv remove requests        # Remove a dependency
uv lock                   # Create or update uv.lock
uv sync                   # Sync environment from project metadata
uv run <command>          # Run a command in the environment
uv run python -c ""       # Run Python in the environment
uv run -p 3.12 <command>  # Run with a specific Python version
```

**Important:**

- Use `pyproject.toml` as the dependency source of truth.
- Use `uv.lock` for reproducible dependency resolution.
- Add or remove dependencies with `uv add` and `uv remove`; don't use
  `pip install`, `uv pip install`, or manual dependency edits.

### Requirements-only projects

**Use when:** An existing project has `requirements.txt` or `requirements.in`
but no `pyproject.toml`.

Migrate it to a modern uv project instead of using the pip interface:

```bash
# requirements.txt only
uv init --bare
uv add -r requirements.txt
uv sync
```

For a pip-tools project, import direct dependencies and retain locked versions
as constraints:

```bash
uv init --bare
uv add -r requirements.in -c requirements.txt
uv sync
```

Import development dependencies separately:

```bash
uv add --dev -r requirements-dev.txt
```

**Important:**

- Inspect recursive includes, constraints, editable packages, Git or local
  dependencies, private indexes, and platform markers before migration.
- Keep the original requirements files until `uv sync` and project tests pass.
- Don't silently fall back to `uv pip` if migration fails; diagnose and explain
  the incompatibility.

### Tools

**Use when:** Running command-line tools (e.g., ruff, ty, pytest) without
installation.

**Key commands:**

```bash
uvx <tool> <args>            # Run a tool without installation
uvx <tool>@<version> <args>  # Run a specific version
```

**Important:**

- `uvx` runs tools from PyPI by package name. Only run well-known tools.
- Use `uv tool install` only when specifically requested by the user.
- If a tool should be locked with the project, use `uv add --dev` and `uv run`.

### Pip interface

**Use when:** The user explicitly requests `uv pip`, pip compatibility, or a
requirements-file workflow that must not be migrated.

**Key commands:**

```bash
uv venv
uv pip install -r requirements.txt
uv pip compile requirements.in -o requirements.txt
uv pip sync requirements.txt

# Platform-independent resolution
uv pip compile --universal requirements.in -o requirements.txt
```

**Important:**

- Don't use `uv pip` merely because `requirements.txt` exists.
- `uv pip install` does not manage `pyproject.toml` or `uv.lock`.
- Don't introduce new requirements files for modern uv projects.
- Don't silently use `uv pip` as a fallback when `uv add` or `uv sync` fails.

## Migrating from other tools

### requirements.txt → uv project

```bash
uv init --bare
uv add -r requirements.txt
uv sync
```

### pyenv → uv python

```bash
pyenv install 3.12       → uv python install 3.12
pyenv versions           → uv python list --only-installed
pyenv local 3.12         → uv python pin 3.12
pyenv global 3.12        → uv python install 3.12 --default
```

### pipx → uvx

```bash
pipx run ruff            → uvx ruff
pipx install ruff        → uv tool install ruff
pipx upgrade ruff        → uv tool upgrade ruff
pipx list                → uv tool list
```

### pip → uv project

```bash
pip install package      → uv add package
pip install -r req.txt   → uv init --bare && uv add -r req.txt && uv sync
pip install -e .         → uv sync
virtualenv .venv         → uv sync
```

## Common patterns

### Use the project interface

```bash
# Bad
pip install requests
uv pip install requests

# Good
uv add requests
```

### Don't run Python directly

```bash
# Bad
python script.py
python -c "..."

# Good
uv run script.py
uv run python -c "..."
```

### Don't manually manage environments

```bash
# Bad
python -m venv .venv
source .venv/bin/activate

# Good
uv sync
uv run <command>
```

### Validate dependency changes

After adding, removing, migrating, or upgrading dependencies:

```bash
uv sync
uv run <project-tests>
```

Report dependency conflicts instead of bypassing the resolver or falling back
to the pip interface.
