## 文档职责

| 位置 | 主要职责 |
| --- | --- |
| `status.md` | 当前研究问题、可用基线、进行中的工作、证据状态、阻碍与近期行动。链接至 EXP 记录，但不替代它们。 |
| `roadmap.md` | 中期目标、研究分支、里程碑、依赖关系，以及停止或转向条件。 |
| `logs/YYYY/YYYY-Www.md` | ISO 周时间线、每日背景、暂定观察与后续步骤。日志链接至 EXP 记录，绝不替代计划或报告。 |
| `experiments/` | 按 EXP 研究问题组织的计划、报告与必要产物。一个 EXP 汇集同一问题的探索性和正式运行，而非每个随机种子或进程。 |
| `knowledge/` | 可跨会话和 EXP 复用的、经整理的知识。 |
| `knowledge/pitfalls/` | 可能复发、根因不明显且值得预防回归的问题。 |
| `decisions/` | 持久性选择的背景、备选方案、理由与权衡。 |
| `protocols/` | 不同研究人员或 Agent 需要一致执行的方法。 |
| `paper/` | 可选的论文大纲、主张-证据映射与图表计划。 |

## 信息归档

1. 在 `status.md` 记录当前有效状态。
2. 在当前周报记录每日工作、临时想法和一次性背景，并链接至适用的 EXP 记录。
3. 在 EXP 计划中记录明确的研究问题。同一问题的所有探索性和正式运行都保留在该 EXP 中；仅在问题实质不同才新建 EXP。
4. 在该 EXP 的报告中记录运行清单和分析，包括成功、失败、异常、中止和无收益运行。
5. 将可跨会话复用的理解沉淀到 `knowledge/`，将反复出现的问题沉淀到 `knowledge/pitfalls/`。
6. 在 `decisions/` 记录持久性选择的理由，在 `protocols/` 记录可重复执行的步骤。
7. 开始论文准备后，在 `paper/claim-evidence-map.md` 记录论文主张、支持与反驳证据、局限性和人工审阅状态。
8. 其他文档仅保留必要摘要和相对链接；不要重复完整的主记录。

## 命名约定

- 周报：`logs/YYYY/YYYY-Www.md`，例如 `logs/2026/2026-W31.md`。
- 实验目录：`experiments/YYYY/EXP-YYYYMMDD-short-slug/`。
- 决策：`decisions/ADR-YYYYMMDD-short-name.md`。
- 主题文档和规程使用稳定、描述性的 kebab-case 名称。避免 `new`、`final` 或 `latest` 等易变状态词。
- 一个实验目录对应一个研究问题。不要为每个随机种子或训练进程创建单独的报告目录。

## Markdown 与 Quarto

状态、路线图、日志、知识、陷阱、决策、规程和实验计划默认使用 Markdown。简单实验报告使用 `report.md`。

仅当报告需要执行 Python 或 R、从结构化数据生成图表或表格、使用复杂公式与交叉引用，或渲染正式的 HTML、PDF 或 Word 输出时，才考虑 `report.qmd`。已安装 Quarto 不代表每份文档都应使用 `.qmd`。

## 维护原则

- 每类信息维护一个主来源；优先链接而非重复。
- 将 `status.md` 保持为当前快照。把历史过程移至日志，把完整实验分析移至报告，把稳定理解移至知识文档。
- 不要为一两句话、一次性错误、小任务或单个随机种子随意创建文件。
- 对已替代的知识、决策和报告标注状态及替代项，同时保留历史理由；不要悄然删除。
- 严格区分观察、解释、结论和决策。人工审阅状态与发现仅记录明确的人工输入。
- 定期检查重复、冲突、过期、信息错位和失效链接。应按职责逐步整理，而非机械拆分为 `part1`、`part2` 等文件。

## 可选工具集成

实验平台可作为完整指标与运行记录的主来源；本文档系统仅保留必要摘要、稳定标识符和链接。Quarto 可执行并渲染复杂报告。Hydra、MLflow、W&B 和 DVC 等工具仅为可选参考，不是本系统的核心依赖。
